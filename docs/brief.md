## Problem & promise
- Problem: Laravel ships a breaking major every year (~Q1); each gets 18 months of bug fixes and 2 years of security fixes. Upgrading means reading the guide, applying dozens of mechanical changes, then fixing breakage, so teams delay until 2-4 versions behind on unsupported releases. Leader's PR is not verified (Laravel Daily review: CI failed because Shift does not run composer update).
- Promise: "Laravel upgrade PRs that prove they work." One verified PR: atomic commits, composer install + build + tests in our sandbox, rule-based repair pass, squawk comments with prompts for your own agent, code never leaves our servers.
- Biggest threat (workbook): free AI paths (Laravel Boost /upgrade-laravel-v13, Copilot, Claude Code, Devin) and Laravel 13 being "a relatively minor upgrade". Value moves to deterministic recipes, verified results, scheduled stay-current PRs, and a multi-repo agency view.
- Gaps we exploit: price ($99-$2,999/yr plans with nothing between and free DIY); verification; code custody (leader's AI Review is +$9 and uses an external AI model); no free scan at leader; no agency fleet dashboard or client report; stranded Laravel 10/11 base.

AC: correct on 50 fixture repos; 500 repos load <1.5 s.
4. Free scan (FR-06,52): report without cloning (manifest + lockfile only) with applicable recipes and effort band S/M/L/XL; in-house EOL calendar + Laravel release watcher. AC: new Laravel tags detected within 1 h on replayed feed.
5. Sandboxed runs (FR-09,10,11,12,13,14,15): fresh isolated sandbox per run on our runner servers, destroyed after; each recipe = one commit; composer.json constraint rewrite + composer update + lockfile; skeleton/config 3-way diff vs tagged laravel/laravel (conflicts become squawks); npm ci + Vite build + tests (Pest/PHPUnit); 25-min wall clock and 8 GB RAM; egress limited to our mirrors and customer's git host. AC: no filesystem/process survives (audit test); over-limit runs open a draft PR marked "timed out"; blocked hosts logged.

7. Rule-based repair pass (FR-17,18): match composer/build/Larastan/test failure output against repair-rule library, apply deterministic fix, re-verify up to 3 loops, separate "Repair: <rule keys>" commit; every unresolved squawk gets a templated agent-ready prompt (file paths, failing output, upgrade-guide link; no AI call). AC: no network call leaves our servers; loop stops after 3 or when no rule matches.
8. PR delivery (FR-20,21,22): PR body as "Work Order" (summary, recipes, verification, squawk index); squawk comments on exact lines with severity Must fix / Review / Note; GitHub check run "Stepclimb by BufferSol · Verified" pass/fail/neutral. No tests -> amber "Unverified" stamp.
9. Autopilot (FR-34): weekly grouped dependency PR per repo, verified; refreshes rather than duplicates (Mon 06:00 repo timezone, default America/New_York).
10. Billing (FR-37,38,39,40): checkout for one-offs and subscriptions via payment processor; webhooks update our own entitlements within 30 s; own invoices/receipts with UK VAT / Canadian GST IDs as PDF; plan limits enforced with upgrade prompt not error; cancel at period end, pause up to 3 months.

## Core user flow
Onboarding (sheet 11):
1. Landing: "Scan a repo free" -> GitHub App install (offer "request approval" email template if user lacks org-admin).
2. GitHub install: select repos; webhook creates Account/Installation/Repo rows, queues scans (over 200 repos: paginate, scan 20 most recently pushed first).
3. Hangar (fleet): repos with detected Laravel version (non-Laravel tagged "Not supported yet").
4. Inspection Report: versions behind, EOL date, applicable recipes, effort band, risk flags (abandoned packages; private packages -> "auth needed").
Core job: Click "Open upgrade PR to Laravel 13" -> plan/credit check or checkout -> Work Order (run) view: runner clones in sandbox, applies recipes as atomic commits, composer update + npm build + tests, repair pass (max 3 loops) -> GitHub PR with work-order body, squawk comments and Verified check -> user reviews, pushes fixes or comments `/stepclimb rerun`.
"Aha": the Verified check/Return-to-Service stamp with test counts (e.g. "VERIFIED: 214 tests passed"). Activation target: first PR on a public repo is free; definition of done for MVP is private Laravel 12 repo -> scan -> pay $9.99 -> PR within 15 minutes.
Other flows: autopilot (turn on weekly deps/monthly conventions; closing supersedes; 3 closed in a row -> suggest quiet mode); upgrade/billing (annual default, proration, downgrade below repo count -> extra repos read-only); cancellation (shows what stops, pause offer, deletion in 30 days); agency report (select repos -> white-label PDF).
Journey: Aware (EOL guides, real public PR) -> Consider (security page, sample work order, dated comparison) -> Sign up -> Activate (scan names their actual files/EOL dates) -> Pay (invoices with tax IDs) -> Retain (weekly PRs, EOL alerts, release-day email) -> Refer (badge, 1 free month each).

## Design direction
Concept: "the maintenance hangar logbook." Repos = airframes in a hangar; each upgrade = a WORK ORDER with numbered tasks; each recipe = logbook ENTRY; open issues = SQUAWKS; green Verified check = "Return to Service" STAMP; new Laravel release = "service bulletin". Fits deterministic, traceable, "careful mechanic" trust story.
- Mood: Exacting, Calm, Legible, Mechanical, Signed-off. Avoid playful/magical/"supercharged"/"AI-powered".
- Palette light: primary Inspection teal #0B5D6B (hover #084A55, soft #E6F1F3), ink #14191C, muted #4E5A61, paper #F7F9FA ("cool, not cream"), surface #FFFFFF, rule #D5DCE0, success Return-to-service green #1F7A3E, warn Safety amber #E8A200 (use ink text on amber, never white), error Red tag #B42318, info Bulletin blue #2F5C8A. Dark "night shift": paper #0F1417, surface #172026, ink #E7EDF0, muted #9AA8B0, primary #4FB3C3, success #4CC27A, warn #F5B935, error #F0645A, rule #2A363D. Amber only for squawks/warnings, green only for verified, red only for must-fix.
- Type: display Archivo (wdth 87.5-100; stamps uppercase +4% tracking), body Public Sans, mono IBM Plex Mono (diffs, versions, SHAs). Scale: display-xl 48/1.05/700 (34 mobile), display-l 36 (28 mobile), h1 28, h2 22, h3 18, body 15/1.55, small 13, stamp 12/700 uppercase, mono 13 tabular. Spacing 4px base (4..96); table rows 32px dense / 40px comfortable. Radius none/3px/6px; sheets 0; stamp 2px with double 1.5px border. Shadow sheet `0 1px 0 rgba(20,25,28,.06), 0 8px 24px -12px rgba(20,25,28,.18)`; popover `0 12px 32px -8px rgba(20,25,28,.28)`; dark uses border. Motion fast 120ms, base 180ms, stamp 160ms `cubic-bezier(.3,1.4,.6,1)` scale 1.06->1; honour prefers-reduced-motion. Breakpoints 480/768/1024/1280; rail collapses <1024. Focus ring 2px primary + 2px offset. CSS vars `--lsb-*` mapped to Tailwind v4 @theme; dark under `[data-theme=dark]` and prefers-color-scheme.
- Layout: document-first. Work Order is hero object (paper-like sheet with header block: airframe=repo, from->to version, date, technician=recipe engine version; numbered task rows; sign-off strip).
