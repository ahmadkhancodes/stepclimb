# Decisions

Standing decisions are in docs/factory/BATCH1_PLAN.md (Mongo instead of Postgres, Better Auth, Stripe first, Mailer interface, Vercel-first, keep 3 deployments).

| ID | Date | Decision | Why |
|---|---|---|---|
| D-01 | 5 Nov 2026 | Upgrade runs execute in Vercel Sandbox microVMs created from a prebuilt runner snapshot, behind a `RunnerBackend` interface. | Spike passed (PHP 8.5, Composer, Laravel 13 tests, egress to Packagist and GitHub). VPS Docker runner implements the same contract later. |
| D-02 | 5 Nov 2026 | All Vercel work uses `VERCEL_TOKEN_NEW_ACCOUNT` via REST or CLI. The Vercel MCP connector in sessions points at the older account (`muhammad-ahmad-khans-projects`) and must not be used for Stepclimb. Project `stepclimb` created in team `ahmad-code` (`prj_EhsJQAA5N2Mnbc5LNyLVJEfjMFsN`). | Owner rule: new account only. |
| D-03 | 5 Nov 2026 | GitHub sign in is the only auth at MVP (plus optional TOTP). Magic link stays in the kit but is off. | Brief: GitHub OAuth, account age gating for the free tier; users map to installations. |
| D-04 | 5 Nov 2026 | Installation tokens never enter the sandbox: Vercel network policy `injectionRules` add the git auth header for `github.com`. Orchestrator functions (not the VM) create PRs, checks and comments. | Smaller blast radius than the brief's own model if a customer test suite is hostile. |
| D-05 | 5 Nov 2026 | GitHub App credentials are stored encrypted in Mongo by the manifest callback, not pasted into env. | Zero manual copy, one click for the owner. |
| D-06 | 5 Nov 2026 | Job queue and schedulers: Mongo leased `jobs` plus a Cloudflare Worker cron every minute; Vercel Cron as a daily backstop. | Hobby cron limits, Pro optional, VPS later. |
| D-07 | 5 Nov 2026 | Sub processor honesty: first release lists Vercel, MongoDB Atlas, Cloudflare, Stripe and the email provider. The brief's "payment processor only" line returns with the VPS phase. Agencies see the real egress allow list controls; first release is "beta for agencies". | Brief's own model needs always on servers; we do not overclaim. |
| D-08 | 5 Nov 2026 | Design overrides recorded in `docs/DESIGN.md` section 12: three font families, light only (dark mode removed 12 Nov 2026), solid hero heading, Phosphor icons, snapped type scale. | Playbook allows written ICP overrides. |
| D-09 | 5 Nov 2026 | Mongo free M0 has no backups, so a nightly export to R2 plus restore drill is part of P0-1. Upgrade the cluster tier when paying customers arrive. | Data safety. |
| D-10 | 5 Nov 2026 | GBP and CAD estimates use the ECB reference rate fetched server side with its date shown; billing stays USD. | Brief asks for estimates only and gives no rates. |
| D-11 | 5 Nov 2026 | Refund policy placeholder `{{refund_policy}}` until the owner sets terms; default proposal: full refund of a one time run within 7 days if the PR is not Verified and the repo has tests. | Brief mentions a refund policy without terms. |
| D-12 | 5 Nov 2026 | Engine lives in a standalone `engine/` package (pure TS: `detect`, `recipes`, `repair`; data in `recipes/` and `repair-rules/`). It has no I/O beyond YAML loaders, no network, no process spawning; sandbox commands are returned as `ExternalStep`s for the run agent. | Orchestrator asked for pure modules before kit-v1; testable without UI or DB and portable to the VPS runner. |
| D-13 | 5 Nov 2026 | Recipes and rules carry `unverified: true` unless the fact came from an official Laravel upgrade guide fetched during the build. Unverified recipes make no change and emit a Review squawk. Repair rule failure texts are from knowledge of Composer's message format and need confirmation against real runs (M3 fixture corpus). | Content honesty; the pass rate is the product. |
| D-14 | 5 Nov 2026 | Engine moved to `src/lib/engine/*` inside the kit layout; vitest includes `src/lib/engine/**/*.test.ts`; recipe and rule YAML stay at repo root `recipes/` and `repair-rules/` (tests read them via `process.cwd()`). | One package, one test run, no second node_modules. |
| D-15 | 5 Nov 2026 | Plan model: `PlanId` free, solo, legacy_solo, studio, legacy_studio, agency; `Interval` adds `half` (Stripe month x 6, lookup suffix `semiannual`); Solo plans are per repo (Checkout adjustable quantity 1 to 200, entitlement `quantity` is the repo limit); one time credits are `oneOffs` with lookup keys `stepclimb_credit_*`. | Brief pricing table. |
| D-16 | 5 Nov 2026 | Stripe catalogue created with the connector (test mode) because `STRIPE_SECRET_KEY_TEST` has not arrived; ids in `docs/STRIPE.md`. `npm run stripe:setup` stays idempotent for later. | Orchestrator instruction. |
| D-17 | 5 Nov 2026 | Production host assumed `stepclimb.vercel.app` until confirmed at first deploy (`NEXT_PUBLIC_APP_URL`). | The project has no deployment or alias yet. |
| D-18 | 5 Nov 2026 | Product collections (installations, repos, apps, scans, webhook_events, github_app) go through a small `Db.docs` document store (put, insert, get, find, remove) with a memory and a Mongo implementation, ids `${app}:${id}`. | Works on the memory driver today, no per collection method sprawl on `Db`; typed wrappers live in `src/lib/github/*`. |
| D-19 | 5 Nov 2026 | The kit has no encryption helper, so `src/lib/crypto.ts` uses WebCrypto AES-256-GCM keyed by SHA-256 of `APP_ENCRYPTION_KEY` (format `v1.<base64url>`). The app JWT is signed with `node:crypto` (accepts GitHub's PKCS#1 PEM). No Octokit; a thin `fetch` client with an injectable fetch and a fixture client (`GITHUB_FIXTURES=1`). | Smallest dependency surface; no network in tests. |
| D-20 | 5 Nov 2026 | Installations are claimed by an org through the setup URL (`installation_id`, only if unclaimed and under 15 minutes old, or the installation account login equals the user's GitHub login) or automatically by login match on the Hangar. Webhook deliveries are recorded after a successful apply; handlers are idempotent. | GitHub's setup redirect is unsigned, so a stale or foreign id must not be claimable. |
| D-21 | 5 Nov 2026 | Engine imports use extensionless specifiers (no `.js`). | Turbopack could not resolve `export * from './x.js'` to `.ts`, which broke the build once the engine was imported by routes. |
| D-22 | 7 Nov 2026 | Runs are built on a `RunnerBackend` contract plus a `RunEnv` seam: the run agent is plain TypeScript that never spawns processes, so the same code runs in the fake runner (tests), inside a Vercel Sandbox and later on a Firecracker VPS. The `@vercel/sandbox` SDK is not added until the adapter is written and can be exercised (no network in this build). | Tests must not touch a network or a real sandbox; keeps dependencies to what is verified. |
| D-23 | 7 Nov 2026 | Pay per run uses the existing one off prices only: the hop picks the credit kind (to 13 `to_latest`, to 12 `to_previous`, older `older_hop`), a paid `mode=payment` Checkout grants one credit via the webhook (idempotent per session id, expires after 365 days), subscribers (solo, studio, agency plans) need no credit. A credit is returned when nothing was delivered (failure, cancel, timeout without a pushed branch). | Brief pricing, no new pricing; refund rule D-11 stays the human policy for delivered PRs. |
| D-24 | 7 Nov 2026 | The fixture pass rate is measured with a simulated Composer resolver (`src/lib/runs/simulated-verify.ts`) over 20 generated apps per hop, with one app in five using a package no rule covers. It tests recipes, repair rules and the agent together but is not a claim about real repos. | Honest reporting; real rates come from sandbox runs of open source Laravel apps. |
| D-25 | 7 Nov 2026 | Better Auth rate limiting is disabled only when `E2E_OUTBOX=1` (never set on Vercel). | The e2e suite signs in more than 5 times a minute from one IP. |

| D-26 | 7 Nov 2026 | Autopilot is one `autopilot` run kind on the same run machinery. The agent has a `deps` mode (`RunEnv.updateDeps`, then the normal verify and repair loop), always pushes the fixed branch `stepclimb/autopilot`, and finalize refreshes the open PR (`updatePr`, new check run) instead of opening a second one. State per repo lives in `autopilot_state` (week key, open PR, closed streak). Paid plans only, no credits. | Brief P0-9: refresh rather than duplicate; reuse the verified pipeline; keeps the VPS runner contract unchanged. |
| D-27 | 7 Nov 2026 | Schedule is an hourly cron that selects repos whose local time (Intl, so DST is right) is Monday 06:00 to 06:59, once per ISO week key. Three unmerged closes in a row set `quietSuggested`; quiet mode is only ever turned on by the user. | Brief and flow wording ("suggest quiet mode"). The Cloudflare worker calls `autopilot` at minute 0 and `backup` at 02:00 UTC; Vercel Cron stays a daily backstop for `alerts`. |
| D-28 | 7 Nov 2026 | Catch up (`chainTo`): a verified hop starts the next hop on top of its branch (stacked PRs, one credit or plan check per hop) until the target. It stops, and records `chainStopped`, on any start error (payment, concurrency, path off). The fake runner resolves a stacked base from branches it pushed. | "Laravel 10 catches up to 13 as three PRs"; stacking keeps each PR reviewable and avoids waiting for merges. |
| D-29 | 7 Nov 2026 | Free tier: when no plan covers the run and no credit exists, a public repo, a GitHub account at least 30 days old (public `GET /users/:login`, cached 7 days) and no other free PR this calendar month give a free run (`billing.via = free`). Runs that delivered nothing do not use the month. | Brief activation target (first public PR is free) and P0-12 gating. |
| D-30 | 7 Nov 2026 | Hard bounces and complaints suppress the address on scope `all`, and `sendMail` now checks suppression for every category (transactional included). Unsubscribe is per scope (`notification`); the GET page only asks, the POST (button or RFC 8058 one click) acts, so link scanners cannot unsubscribe anyone. Provider webhook is Svix signed (Resend). | Protects the sending domain; matches the P0-11 acceptance (bounce suppressed within a minute, unsubscribe works). |
| D-31 | 7 Nov 2026 | ALTCHA is enforced on the magic link form (per IP and per address limits first, then a single use proof in `x-altcha`, solved in the browser with `altcha-lib`). Cost lowered to 1,000 iterations and a counter of 500 to 2,000 so the proof takes well under a second on a phone; the rate limits carry the weight. Off only when `E2E_OUTBOX=1`. | Public form protection without a third party; the first cost setting blocked the main thread for many seconds. |
| D-32 | 7 Nov 2026 | Founder console requires TOTP in production (`founderNeeds2fa`; off only under `E2E_OUTBOX=1`). Pins (`pins/global`) switch a recipe or rule off or hold it to a version, applied inside the run agent through the run spec so any runner honours them. Upgrade paths switch with config flags `path_laravel_<from>_to_<to>` = `off`. Refund tool returns the credit, or refunds the Checkout payment through Stripe only for sessions tagged `metadata.app`, and each run is refunded once (`creditRefunded`). | Brief P0-12 admin scope; keeps Stripe access to this app's objects. |
| D-33 | 7 Nov 2026 | Backups export every product collection (`BACKUP_COLLECTIONS` on the memory driver, every collection except sessions and counters on Mongo) as gzip JSON with a sha256; the nightly job always writes a manifest (counts, checksum) and stores the file only when a `BackupSink` exists (R2 later). The restore drill restores into a scratch database and compares counts. Alerts mail the founder once an hour per key. | The free Atlas tier has no backups; R2 does not exist yet. |
| D-34 | 7 Nov 2026 | The e2e suite runs with one worker. | The specs share one server, one process wide memory DB and one fixture GitHub account that `seed-github` reclaims, so parallel files raced. |
| D-35 | 7 Nov 2026 | The token the sandbox can use is read only (`contents: read`). The agent hands its commits back over the signed callback (git bundle) and the orchestrator pushes, only to `refs/heads/<expectedBranch>` (computed on our side), force only for `stepclimb/autopilot`. The orchestrator never trusts a branch or sha from the sandbox: PRs use `expectedBranch(run)`, the check run goes on the head GitHub reports for it, and every result is sanitised before it reaches GitHub. | Customer code and its dependencies run next to the agent and can use anything the VM can use (injected token, event secret). REVIEW P0-2, P0-3, P0-5. |
| D-36 | 7 Nov 2026 | The accessibility gate injects `node_modules/axe-core/axe.min.js` (already in the lockfile through eslint-plugin-jsx-a11y) into Playwright pages instead of adding `@axe-core/playwright`. | No new dependency; same rules engine. If the transitive copy disappears, add axe-core as a dev dependency. |
| D-37 | 7 Nov 2026 | A GitHub installation is linked to an account only when GitHub lists it for the user's own sign in token (`GET /user/installations`) or it is a personal install matching the user's GitHub login. Users who signed in by email are asked to sign in with GitHub to link. | The setup redirect's `installation_id` is unsigned and guessable (REVIEW P0-1). |
| D-38 | 7 Nov 2026 | `E2E_OUTBOX` and `GITHUB_FIXTURES` take effect only when `VERCEL_ENV` is not `production` (`e2eMode()`, `fixturesMode()`). Run logs are deleted 30 days after a run ends (`retention` daily job). `/api/health` reads the database and answers 503 when it cannot. | Test switches must not be able to open production; the security page promises 30 day logs; uptime checks must see a database outage. |
- 2026-11-10 Indexes: ensureIndexesOnce runs un-awaited on first connection (memoized per instance, no build-time run, errors logged scrubbed, code 85/86 conflicts skipped); `npm run db:indexes` kept for manual use.
| D-DM | 12 Nov 2026 | Dark mode removed completely: product is light only (no toggle, no OS fallback, one theme-color). Guarded by tests/unit/no-dark-mode.test.ts. Dark rows in docs/DESIGN.md section 5 and the playbook are historical. |

Guarded by tests/unit/design-system.test.ts. | Founder judged the old UI "typical AI". Audit of laravelshift.com, getrector.com, laravel.com, forge.laravel.com, spatie.be, laravel-news.com (docs/design/refs/2026-11-12/) showed red, coral, teal, blue and green are taken; dates are what triggers this ICP and nobody shows them. |
